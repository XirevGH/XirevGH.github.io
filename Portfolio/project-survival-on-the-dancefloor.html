Survival on the Dancefloor

A Rhythm-Based Survivor-like Roguelite - 7 Week Team Project

Role: Lead Gameplay & Systems Programmer Team Size: 6 Time: 7 Weeks Unity C# Roguelite Audio & Graphics Architecture
View Source Code on GitHub

Game Overview

Developed over 7 weeks in Unity (C#) as a 6-person team project, Survival on the Dancefloor is a fast-paced survivor-like pixel roguelite set inside an unforgiving retro nightclub. Trapped on an infinite dancefloor, players must battle swarms of mad bouncers, dancers, and drunk patrons for as long as possible.

The core gameplay combines musical tempo directly with weapon firing rates: players catch musical notes scattered across the floor to accelerate the song's BPM and speed up attack execution. Missing notes causes the music and weapons to decelerate to a crawl. Players gain XP, select music-themed weapons and utilities from a random selection on level-up, defeat powerful bosses, and purchase permanent upgrades after each game.

Core Technical Implementation

1. Hierarchical Upgrade Architecture & JSON Persistence

Progression and meta-progression are handled through an extensible OOP hierarchy and reflection-driven stat modifications, built specifically to eliminate manual UI labor in the Unity Editor:

  • Automated UI Data-Binding Pipeline: The primary goal was eliminating UI hierarchy bloat. The naive approach would have required creating individual buttons for every single upgrade across all 3 draft panels (75+ buttons in total), making adding new abilities a tedious manual chore. Instead, a single generic panel dynamically binds icons, localized text, and action payloads at runtime based on clean naming conventions.
  • Polymorphic Item Hierarchy: Separates active musical Weapons (Bass Guitar, Electric Guitar, Synthwave Blast, Saxophone, Yoyo, Disco Ball, Vinyl Disc, Breakdance) from passive Utilities (Roller Skates for speed, Groove Armor for health, Chill Vibe for enemy slow, Personal Space for pushback).
  • Reflection-Driven Modifiers: C# reflection queries item types and method names at runtime, enabling detailed upgrades across projectile counts, penetration limits, damage values, and area radii without switch-case bloat or manual inspector hookups.
  • Cross-Session JSON Save Data: Meta-progression ranks, lifetime stats, and currency are serialized to persistent JSON files, allowing progress retention between runs and the main menu meta-shop.
  • Boss Encounters & Drop Containers: High-health boss encounters drop special loot containers (Purse.cs) that reward players with bonus upgrades extracted dynamically from the active upgrade pool.

2. Combat Hit-Registration, Proximity Targeting & Trajectories

The combat engine powers an arsenal of musical weapons with specialized collision, targeting, and movement behaviors:

  • Directional Melee Hit-Validation: The Bass Guitar swing uses a HashSet<Collider2D> to record hit enemies during an active swing (BassGuitarSwing), automatically flushing references upon returning to idle (BassGuitarIdle) to prevent duplicate damage ticks per frame.
  • Proximity Sorting with SortedSet: The Electric Guitar lightning attack gathers enemies inside a circular trigger and sorts them by distance using a SortedSet<GameObject> with a custom distance comparer (GameObjectComparer), cleanly tethering the closest units via LINQ (Take(amountOfTethers)).
  • Trajectory Mathematics & Dual-Stick Aiming: Projectiles utilize quadratic Bezier curve trajectories (WaveTime.cs) for boomerang Vinyl Discs, orbiting paths for Yoyos, and 360-degree Mathf.Atan2 vector calculations for independent joystick aiming.

3. Multi-Camera Rendering & Selective 2D Bloom Pipeline

To achieve a punchy retro nightclub aesthetic without washing out gameplay elements, the visual pipeline uses a 3-camera architecture with isolated 2D light layers:

  • Isolated Camera Hierarchy: Scene rendering is split across three dedicated cameras: a Floor Camera, an Objects/Player Camera, and a World-Space UI Camera.
  • World-Space UI for Particle System Integration: The UI canvas is built in World Space rather than Screen Space Overlay, allowing Unity Particle Systems (for confetti popups) to render when leveling up or earning bonus upgrades.
  • Selective Post-Processing Volumes: Dedicated Bloom volumes allow high-intensity, pulsating neon light on the dancefloor without overexposing character sprites, enemies, or UI elements.
  • Procedural Viewport Tilemap: Built an automated floor generation script that checks camera viewport bounds to recycle tiles dynamically with weighted 7-color palette distributions.

4. Event-Driven Audio Synchronization & Dynamic BPM Modulation

Instead of standard delta-time timers, weapons and rhythm visuals fire in strict synchronization with the music track using a centralized, sample-accurate event engine (TriggerController):

  • Sample-Accurate Audio Timing: The controller reads raw playback samples (inGameMusic.timeSamples) divided by the clip frequency (clip.frequency) and interval length. This ensures beat tracking remains anchored directly to the audio buffer without drifting during framerate spikes or pitch shifts.
  • Dynamic Musical Subdivisions: Each configurable Trigger object calculates its interval dynamically via 60f / (BPM / noteValue), allowing simultaneous tracking of whole notes, quarter notes, and custom subdivisions.
  • Discrete Integer Beat Detection: By monitoring transitions in the floored interval index (Mathf.FloorToInt(interval) != lastQuaterNote), the system executes events exactly once per musical step and broadcasts to registered weapons via UnityEvent delegates.
  • Original Audio Synthesis: Synthesized custom 80s synthwave sound effects (level-up chimes and death stings) from scratch using modular synthesis in VCV Rack.

5. Custom Editor Tooling, UI Pipeline & Multi-Language Localization

To streamline development and support internationalization, custom editor tooling and UI systems were built:

  • Custom Unity Editor Inspector (`DynamicJoystickEditor.cs`): Built custom inspector tooling using SerializedProperty to configure screen-split touch zones for movement and aiming.
  • Touch Joystick Snap-Back Fix: Customized dynamic touch controls to automatically reset to their home anchors on release, preventing stuck inputs on mobile devices.
  • Multi-Language Localization Engine: Built a custom text parser supporting 4 languages (English, Swedish, Dutch, and Thai), dynamically formatting method names, upgrade stats, and symbols into UI templates.
  • LeanTween UI & Haptics: Programmed modal scale transitions, scroll rect centering on selected items, screen flash feedback, and mobile hardware vibration on player damage.

Key Challenges Overcome

UI Hierarchy Bloat vs. Automated Data-Binding:

Automated UI Data-Binding Pipeline: The primary goal was eliminating manual UI labor and hierarchy bloat. Supporting 27 individual upgrades across 13 separate items created 40 unique selectable states. The naive approach would have required 40 individual buttons inside each of the 3 draft panels (120 buttons in total) and complex runtime visibility toggling. Instead, 3 generic panels dynamically bind icons, localized text, and reflection method payloads (PrepareMethodToExecute) at runtime based on standardized naming conventions.

Post-Processing Overexposure on Layered 2D Sprites:

High-intensity bloom needed for the dancefloor severely overexposed the player sprite and UI. Splitting rendering across a 3-camera architecture with isolated layer volumes allowed the dancefloor to flash vibrantly while characters and UI remained crisp.

Dynamic Music Tempo & Attack Synchronization:

Modulating track pitch and tempo in real time as players gathered or missed ground notes caused frame-based attack timers to drift. Polling active audio playback time inside an event-driven TriggerController ensured attack frequencies accelerated and decelerated in perfect sync with the music.

Multi-Hit Trigger Glitches on Continuous Swings:

Melee hitbox colliders caused duplicate damage ticks per frame during active swing animations. Implementing a state-bound HashSet<Collider2D> ensured enemies take damage exactly once per swing cycle and flushed references cleanly on idle.

Dynamic Proximity Target Selection:

Finding and tethering the closest enemies in dense hordes caused performance hiccups with standard array sorting. Passing targets through a SortedSet<GameObject> with a custom distance comparer allowed clean, efficient extraction of the nearest candidates.

Project Outcome

Delivered over the 7-week development cycle, the game achieved:

  • A complete survivor-like roguelite loop with tempo-driven horde combat and custom audio synthesis
  • A modular C# item hierarchy with persistent JSON meta-progression and 4-language localization
  • A performant multi-camera 2D rendering pipeline with selective post-processing bloom
