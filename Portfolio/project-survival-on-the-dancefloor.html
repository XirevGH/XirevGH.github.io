Survival on the Dancefloor

Rhythm-Infused Survivor-like Roguelite - 7 Week Team Project

Role: Lead Gameplay & Systems Programmer Team Size: 6 Time: 7 Weeks Unity C# Roguelite Audio & Graphics Architecture
View Source Code on GitHub

Game Overview

Developed over 7 weeks in Unity (C#) as a 6-person team project, Survival on the Dancefloor is a fast-paced survivor-like roguelite set in a retro disco nightclub. Taking inspiration from Vampire Survivors, the core gameplay blends rhythmic tempo with horde combat: the musical BPM directly drives attack execution, while players navigate a procedural dancefloor, defeat enemies for loot drops, and build modular weapons with persistent meta-upgrades.

Core Technical Implementation

1. Event-Driven Audio Synchronization & Beat Dispatching

Instead of using unconstrained update timers, combat actions and rhythmic visuals are synchronized directly to the audio track using a centralized event engine (TriggerController):

  • BPM-Driven Subdivisions: The controller tracks the track's active playback time and calculates note intervals dynamically, exposing delegate registration for quarter notes, half notes, and whole bars.
  • Modular Listener Registration: Weapons, UI note meters, and camera pulsing subscribe their attack methods to specific beat indices via UnityAction listeners directly in code or the inspector.
  • Original Audio Synthesis: Synthesized custom 80s synthwave sound effects (level-up chimes and death stings) from scratch using modular synthesis in VCV Rack.

2. Multi-Camera Rendering & Selective 2D Bloom Pipeline

To achieve a punchy retro nightclub aesthetic without washing out gameplay elements, the visual pipeline uses a 3-camera architecture with isolated 2D light layers:

  • Isolated Camera Hierarchy: Scene rendering is split across three dedicated cameras: a Floor Camera, an Objects/Player Camera, and a Screen Space UI Camera.
  • Selective Post-Processing Volumes: Dedicated Bloom volumes allow high-intensity, pulsating neon light on the dancefloor without overexposing character sprites, enemies, or UI elements.
  • Procedural Viewport Tilemap & Shaders: Built an automated floor generation script that checks camera viewport bounds to recycle tiles dynamically with weighted 7-color palette distributions, complemented by a custom Shader Graph distortion effect for the ChillVibe slow aura.

3. Combat Hit-Registration & Distance-Sorted Proximity Targeting

Weapons support both melee hit-validation and dynamic proximity targeting:

  • State-Bound HashSet Hit-Validation: The Bass Guitar swing uses a HashSet<Collider2D> to record hit enemies during an active swing (BassGuitarSwing), automatically flushing references upon returning to idle (BassGuitarIdle) to prevent duplicate damage ticks per frame.
  • Proximity Sorting with SortedSet: The Electric Guitar lightning attack gathers enemies inside a circular trigger and sorts them by distance using a SortedSet<GameObject> with a custom distance comparer (GameObjectComparer), cleanly tethering the closest units via LINQ (Take(amountOfTethers)).
  • Trajectory Mathematics: Projectiles utilize quadratic Bezier curve trajectories (WaveTime.cs) for curving disc attacks and 360-degree Mathf.Atan2 vector calculations for independent dual-stick aiming.

4. Hierarchical Upgrade Architecture & JSON Persistence

Progression and meta-progression are handled through an extensible OOP hierarchy and reflection-driven stat modifications:

  • Polymorphic Item Hierarchy: All items inherit from an abstract Item base class, sub-classed into Weapon, ProjectileWeapon, TetheringWeapon, PermanentProjectileWeapon, and Utility.
  • Reflection-Driven Modifiers: C# reflection queries item types and method names at runtime, enabling dynamic in-game upgrades and UI slider bindings without brittle switch-case statements.
  • Cross-Session JSON Save Data: Meta-progression ranks, lifetime stats, and currency are serialized to persistent JSON files, allowing seamless progress retention between runs and the main menu meta-shop.
  • Boss Drop Containers: Implemented a modular drop system (Purse.cs) where defeated bosses drop loot containers that grant single randomized upgrades extracted from the core upgrade pool.

5. Custom Editor Tooling, UI Pipeline & Multi-Language Localization

To streamline development and support internationalization, custom editor tooling and UI systems were built:

  • Custom Unity Editor Inspector (`DynamicJoystickEditor.cs`): Built custom inspector tooling using SerializedProperty to configure screen-split touch zones for movement and aiming.
  • Touch Joystick Snap-Back Fix: Customized dynamic touch controls to automatically reset to their home anchors on release, preventing stuck inputs on mobile devices.
  • Multi-Language Localization Engine: Built a custom text parser supporting 4 languages (English, Swedish, Dutch, and Thai), dynamically formatting method names, upgrade stats, and symbols (such as + and %) into UI templates.
  • LeanTween UI & Haptics: Programmed modal scale transitions, scroll rect centering on selected items, screen flash feedback, and mobile hardware vibration on player damage.

Key Challenges Overcome

🎨 Post-Processing Overexposure on Layered 2D Sprites:

High-intensity bloom needed for the dancefloor severely overexposed the player sprite and UI. Splitting rendering across a 3-camera architecture with isolated layer volumes allowed the dancefloor to flash vibrantly while characters and UI remained crisp.

🎵 Audio Desynchronization Across Variable Framerates:

Standard delta-time update timers caused weapon attack cadences to drift from the music during frame drops. Building an event-driven TriggerController that polls the audio playback position guaranteed frame-independent beat alignment.

⚔️ Multi-Hit Trigger Glitches on Continuous Swings:

Melee hitbox colliders caused duplicate damage ticks per frame during active swing animations. Implementing a state-bound HashSet<Collider2D> ensured enemies take damage exactly once per swing cycle and flushed references cleanly on idle.

⚡ Dynamic Proximity Target Selection:

Finding and tethering the closest enemies in dense hordes caused performance hiccups with standard array sorting. Passing targets through a SortedSet<GameObject> with a custom distance comparer allowed clean, efficient extraction of the nearest candidates.

Project Outcome

Delivered over the 7-week development cycle, the game achieved:

  • A complete survivor-like roguelite loop with tempo-driven combat and custom audio synthesis
  • A modular C# item hierarchy with persistent JSON meta-progression and 4-language localization
  • A performant multi-camera 2D rendering pipeline with selective post-processing bloom
