Fool Me Once

Competitive Splitscreen Maze Duel - 5 Day Game Jam

Team Size: 4 Time: 5 Days Unreal Engine 5 C++ Splitscreen Multiplayer Game Jam

Game Overview

Developed during an intensive 5-day game jam in Unreal Engine 5, Fool Me Once is a competitive local multiplayer maze duel designed for physical Dance Dance Revolution (DDR) pads. Two players navigate a futuristic maze arena in splitscreen, racing to collect cakes and deploying unpredictable power-ups and traps to disorient each other.

Core Technical Implementation

1. Discrete Graph Navigation & Vector Directional Parsing

Standard physics and Character Movement components were discarded in favor of a responsive, deterministic Discrete Graph Navigation System using custom AMovementNode actors:

  • Dot-Product Directional Filtering: When a player inputs a movement or turn command, the character calculates the vector dot product between the player's facing direction and all connected graph nodes, validating moves within a tight angular cone (ForwardVectorMatchThreshold = 0.707f, corresponding to $45^\circ$).
  • Look-Ahead Corner Pre-Rotation: To eliminate jarring, angular stops at 90-degree junctions, the movement algorithm checks ahead for the next connected corridor (NextForwardNode). While the pawn is still in transit to its immediate target, it dynamically blends its rotation (TargetForwardRotation) into the upcoming corner using an eased blend factor.
  • Quaternion SLERP & Non-Linear Easing: Rotations are smoothly interpolated via spherical linear interpolation (FQuat::Slerp) alongside custom exponential easing curves (InterpEaseInOut), ensuring crisp and predictable visual feedback.

2. Automated Level-Design Floor Snapping Tooling

To eliminate tedious manual Z-axis alignment and prevent floating or clipping nodes across uneven maze geometry, each AMovementNode performs an automated vertical surface alignment on initialization:

  • Runtime Ground Trace: During BeginPlay(), the node fires a 10,000-unit downward line trace on the ECC_Visibility collision channel.
  • Automatic Z-Height Normalization: Upon striking walkable geometry, the node dynamically snaps its position to Hit.Location.Z + 102.15f, providing guaranteed ground clearance for player capsules without manual level adjustments.

3. Data-Driven Spatial Item Spawning & Count Reconciliation

Collectibles and power-ups are managed centrally by ACakeChaseGameMode, ensuring fair and collision-free spawning across active gameplay nodes:

  • Configurable Power-Up Definitions: Handled via a structured configuration array (FPowerUpSpawnConfig), exposing per-interval spawn probabilities, concurrent entity limits, and polymorphic class hierarchies.
  • Multi-Channel Anti-Overlap Validation: Before spawning an item, the GameMode performs a multi-channel spherical overlap query (SphereOverlapActors querying WorldStatic, WorldDynamic, Pawn, and PhysicsBody) with a 50-unit radius to filter out occupied graph nodes.
  • Self-Healing Count Reconciliation: Includes active world-sweep routines (UpdateActualCakeCount, UpdateActualPowerUpCounts) to ensure internal capacity limits remain accurate even if actors are destroyed or collected asynchronously.

4. Polymorphic Power-Ups & Clean Input Redirection

Power-up effects are structured modularly using an extensible class hierarchy:

  • Extensible Base Architecture: APowerUp serves as an abstract base actor combining a USphereComponent trigger, a visual UStaticMeshComponent, and a custom UPickupComponent, exposing a BlueprintNativeEvent (ApplyEffect) for modular gameplay logic.
  • Clean Input Inversion Mechanics: To implement disorienting trap effects (such as reversed steering), the character uses a dynamic input router (bHasInvertedInput) that remaps forward to 180-degree turns and swaps left/right triggers in place, bypassing the need to reallocate Enhanced Input Mapping Contexts at runtime.

5. Splitscreen Multi-Controller Setup

To support two simultaneous players on physical DDR dance pads, players are dynamically spawned and bound to dedicated viewports and input routing structures.

Key Challenges Overcome

🕹️ Discrete DDR Input vs. Free Movement:

Standard continuous CharacterMovement caused players on dance pads to easily overshoot corners. Replacing it with a graph-based dot-product navigation system gave players tactile, deterministic control over every step and pivot.

🎥 Camera Corner Snapping & Motion Sickness:

Instant discrete 90-degree pivots caused disorientation in first-person splitscreen. Implementing predictive look-ahead rotation and Quaternion SLERP easing created smooth, anticipatory cornering.

📦 Item Overlap Contention:

Periodic spawning in a confined grid caused cakes and power-ups to occasionally spawn on top of active players or existing items. Enforcing a 4-channel spherical overlap query across all static, dynamic, pawn, and physics bodies guaranteed single-occupancy nodes.

Project Outcome

Delivered in just 5 days, the game achieved:

  • A clean, highly responsive discrete node navigation engine in C++
  • Robust splitscreen multiplayer with dynamic item and power-up spawning
  • Positive feedback during playtests for its fluid, anticipatory corner transitions and competitive game feel
