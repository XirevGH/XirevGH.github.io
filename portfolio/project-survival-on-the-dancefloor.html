Survival on the Dancefloor

A Rhythm-Based Survivor-like Roguelite - 7 Week Team Project

Role: Lead Gameplay & Systems Programmer Team Size: 6 Time: 7 Weeks Unity (C#) ScriptableObjects Unity Localization Audio & Graphics
View Source Code on GitHub

Game Overview

Developed over 7 weeks in Unity (C#) as a 6-person team project, Survival on the Dancefloor is a survivor-like pixel roguelite set in a retro nightclub. Players survive waves of bouncers, dancers, and patrons on an infinite dancefloor.

Weapon firing rates are tied to the music tempo: collecting musical notes increases track BPM and attack speeds, while missing notes slows both down. Players level up to choose weapons and utilities, defeat bosses, and buy permanent upgrades between runs.

Core Technical Implementation

1. Weapon Class Hierarchy & ScriptableObject Architecture

All player equipment derives from an object-oriented class structure. The base Item class splits into Weapon and Utility. Weapons branch into specialized behavior types: PhysicalWeapon for melee swings, ProjectileWeapon for shooting notes, TetheringWeapon for lightning arcs, and PermanentProjectileWeapon for projectiles that are generated once and do not disappear. Utilities handle passive stat modifiers like speed boosts, extra health, slow fields, and decoys.

Equipment stats and upgrades are handled with ScriptableObjects and JSON save files:

  • ScriptableObject Data Setup: Base item data is stored in ItemDefinitionSO assets (split into WeaponDataSO and UtilityDataSO). Upgrades use UpgradeDefinitionSO to define stats (StatType), costs, and values.
  • Event-Based Shop UI: Shop buttons (MetaUpgradeNodeUI) subscribe to OnUpgradePurchased and OnCurrencyChanged events on the MetaUpgradeManager, avoiding constant Update() checks.
  • In-Run Card Draft: Level-up choice cards are built dynamically from available items and upgrade assets, wiring button clicks directly to item methods using lambdas.
  • JSON Save System: Save data (MetaSaveData) writes purchased ranks (UpgradeID → Rank) to disk via JSON, keeping ScriptableObjects clean and resetting player stats properly between runs.
  • Results Screen Architecture: ResultManager stays active across scenes to track kills, time, and item assets, while ResultScreenUI reads this data to display the game-over screen.

2. Combat Hit-Detection, Target Sorting & Trajectories

Each weapon uses dedicated targeting and collision logic:

  • Melee Hit Checks: The Bass Guitar uses Animator.StringToHash and a HashSet<Collider2D> to track hit enemies during the swing animation, clearing the set when returning to idle to prevent multi-hits on the same swing.
  • Distance-Based Targeting: The Electric Guitar collects enemies in a trigger and sorts them by distance using a SortedSet<GameObject> with a custom comparer (GameObjectComparer), tethering the closest targets.
  • Custom Movement Paths: Vinyl discs follow a 2-stage quadratic Bezier curve to fly out and return like boomerangs, Yoyos orbit the player using angle math, and aiming uses Mathf.Atan2 for dual-joystick controls.

3. Multi-Camera Setup & 2D Bloom Pipeline

The graphics setup uses three dedicated cameras to keep the retro club look clear during busy combat:

  • 3-Camera Hierarchy: Rendering is split into a Floor Camera, an Objects/Player Camera, and a World-Space UI Camera.
  • World-Space UI: The UI canvas is in World Space so Unity particle systems (like level-up confetti) render properly on top of menus.
  • Isolated Bloom Volumes: Bloom is applied only to the floor layer so the dancefloor lights glow without washing out character sprites or text.
  • Viewport Floor Generation: A tilemap script checks camera bounds to place and remove floor tiles as the player moves, using a 7-color palette.

4. Music Synchronization & Beat Trigger Engine

Weapon firing and beat animations are driven by audio playback timing rather than frame timers via TriggerController:

  • Sample-Based Timing: The script reads inGameMusic.timeSamples divided by clip frequency and trigger interval, keeping beats in sync even when track pitch or BPM changes.
  • Configurable Beat Subdivisions: Each Trigger calculates its interval using 60f / (BPM / noteValue) to track whole notes, quarter notes, and custom fractions while ignoring passive items (noteValue = 0).
  • Integer Beat Tracking: Fires events when the floored interval index changes, sending triggers to registered weapons via UnityEvent callbacks.
  • Custom Sound Design: Created 80s synthwave level-up and death sound effects using modular synthesis in VCV Rack.

5. Unity Localization & Mobile Touch Controls

Language support and mobile input handling were built using standard Unity systems:

  • Unity Localization Package: Item assets (ItemDefinitionSO) and upgrades (UpgradeDefinitionSO) use LocalizedString entries to support 5 languages: English, Swedish, Spanish, Dutch, and Thai.
  • Dynamic Value Insertion: Stat numbers and percentages are passed to LocalizedString.GetLocalizedString(value) to fill in {0} placeholders while keeping correct word order for each language.
  • Locale Change Listener: UI components hook into LocalizationSettings.SelectedLocaleChanged to update displayed text instantly when the language is changed in settings.
  • Mobile Controls & Haptics: Setup screen-split joysticks that snap back to home position on release, with device vibration triggers on player hits.

Key Challenges Overcome

Managing 27 Unique Upgrades Without Hardcoded UI:

With 13 items and 27 upgrades, creating individual UI buttons for every card would have required over 100 manual buttons. Built a ScriptableObject pipeline where 3 reusable card panels populate text, icons, and click actions directly from asset definitions.

Bloom Overexposure on 2D Sprites:

Strong bloom on the dancefloor was blinding the player and hiding UI text. Splitting rendering across 3 cameras with layer-specific post-processing kept the floor glowing while characters and text stayed clear.

Keeping Attacks in Sync During Dynamic BPM Shifts:

Speeding up the track when collecting notes caused delta-time attack timers to desync from the music. Reading raw audio samples in TriggerController kept weapon attacks locked to the beat regardless of pitch or tempo changes.

Formatting Upgrade Numbers Across 5 Languages:

Different languages place numbers and percentages in different parts of the sentence. Used Unity’s LocalizedString Smart Strings so that values passed into {0} format correctly in English, Swedish, Spanish, Dutch, and Thai.

Fast Proximity Target Sorting:

Finding nearest targets in large hordes slowed down with basic array searches. Used a SortedSet<GameObject> with a custom distance comparer to collect and sort nearby enemies cleanly.

Project Outcome

Built over 7 weeks, the project delivered:

  • A complete survivor-like roguelite loop with tempo-synced weapon combat and custom audio effects
  • A modular ScriptableObject equipment system with JSON save files and 5-language localization
  • A 3-camera 2D rendering pipeline with layer-isolated bloom
