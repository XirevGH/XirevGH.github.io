Fool Me Once

Splitscreen Maze Duel - 5 Day Game Jam

Role: Gameplay & Systems Programmer Team Size: 4 Time: 5 Days Unreal Engine 5 C++ Splitscreen Multiplayer Game Jam
View Source Code on GitHub

Game Overview

Developed during a 5-day game jam in Unreal Engine 5, Fool Me Once is a local splitscreen maze runner built to be played on physical Dance Dance Revolution (DDR) dance pads. Two players navigate a space station maze, racing to collect cakes while using power-ups and traps against each other.

Core Technical Implementation

1. Node Navigation & Dot-Product Direction Checks

Instead of standard continuous character movement, I built a discrete grid navigation system using custom AMovementNode actors to match step inputs from DDR pads:

  • Dot-Product Move Checks: When a player steps in a direction, the pawn checks the vector dot product between its forward facing vector and connected node vectors, allowing movement only if the node sits within a 45° forward cone (ForwardVectorMatchThreshold = 0.707f).
  • Corner Rotation Look-Ahead: To prevent abrupt stops at 90-degree turns, the character inspects the upcoming corridor (NextForwardNode) while still moving toward its current target, blending rotation smoothly into the turn.
  • Slerp Rotation: Rotations interpolate with FQuat::Slerp and an ease-in-out curve (InterpEaseInOut) to keep camera and character turning smooth in first-person view.

2. Automatic Node Floor-Snapping Tool

Pawns navigate directly to node pivots, meaning nodes must sit at the exact capsule half-height of the character. To avoid manually adjusting node heights across uneven floors, each AMovementNode snaps itself to the floor on startup:

  • Downward Trace: On BeginPlay(), the node runs a line trace downward on the ECC_Visibility channel.
  • Capsule Center Offset: When floor geometry is hit, the node snaps its Z-position to Hit.Location.Z + 102.15f (the character capsule half-height), ensuring correct ground clearance.

3. Item Spawning & Overlap Checks

Pickups and power-ups are managed by ACakeChaseGameMode to distribute items across unoccupied nodes:

  • Spawn Configs: Uses FPowerUpSpawnConfig structs to define spawn timers, chances, maximum active limits, and classes.
  • Sphere Overlap Checks: Before spawning, the GameMode runs a 50cm SphereOverlapActors check on the target node (querying WorldStatic, WorldDynamic, Pawns, and PhysicsBodies) to skip occupied spots.
  • Active Item Tracking: Tracks live cake and power-up counts to maintain target numbers when items are collected.

4. Power-Up Base Class & Inverted Controls

Power-up and trap logic:

  • Base Power-Up Actor: APowerUp provides a shared base with a collision sphere, mesh, and UPickupComponent, exposing a BlueprintNativeEvent (ApplyEffect) to build new power-ups in Blueprints.
  • Inverted Input Trap: The inverted steering trap sets bHasInvertedInput on the pawn, which flips forward movement to 180-degree turns and swaps left/right inputs directly in code without needing to change input mapping contexts.

5. Splitscreen Setup for DDR Dance Pads

Players are spawned on game start, splitting the viewport horizontally and mapping separate controller IDs to the two physical dance pads.

Key Challenges Overcome

DDR Mat Movement vs. Standard Continuous Movement:

Standard continuous CharacterMovement caused players stepping on physical DDR pads to overshoot corridor turns. Replacing physics movement with a node-based step system gave players direct, discrete control that lined up with physical foot taps.

First-Person Camera Snapping on 90-Degree Turns:

Instant 90-degree pivots caused disorientation in splitscreen. Added look-ahead corridor checks and FQuat::Slerp easing to blend camera rotation into the turn while the player moves.

Pickups Spawning on Occupied Nodes:

Items occasionally spawned on top of players or other items in narrow hallways. Added a sphere overlap check across Pawns, PhysicsBodies, and World objects to filter out occupied nodes before spawning.

Project Outcome

Delivered in 5 days, the game achieved:

  • A discrete node movement system in C++ tailored for physical DDR pad input
  • Local splitscreen multiplayer with dynamic item spawning and trap effects
  • Smooth 90-degree corner easing with predictive camera rotation
